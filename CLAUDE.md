# CLAUDE.md — CAIRN guidance for Claude Code

This file tells Claude Code how to work in this repo. Follow it as though

## Standing orders (non-negotiable)

- **Always run the tests before marking any task complete.** `pytest -q`
  at minimum; a passing run is the gate for "done," not code that looks
  right. If the tests don't cover the change, add the test first.
- **Never create files outside the project directory.** No writes to
  `~`, `/tmp`, sibling repos, or any path that isn't under the current
  repo root. If a task seems to require it, stop and ask.
- **Ask before deleting any file.** Even obvious-looking scratch files
  (dumps, one-off outputs) can be user WIP — confirm before `rm` or
  before removing a tracked file in git.
- **Explain reasoning before writing code.** For anything more than a
  one-line fix, write a sentence or two describing what you'll change
  and why *before* the first edit. The user should be able to redirect
  you before the diff lands.
- **If unsure, ask — don't guess.** Ambiguous requirements, missing
  context, uncertain API shapes: surface the question rather than
  pick a path and hope. Guessing once is faster; guessing wrong
  compounds across a session.

## What this project is

A multi-detector fusion pipeline for classifying whether text was written
by a human or generated by an LLM. Three runtimes share one SPA:

- `cairn gui` — stdlib HTTP + `cairn/gui/static/index.html` (single file SPA)
- `cairn serve` — FastAPI (needs `cairn[api]`)
- Tauri desktop shell — `src-tauri/` wraps a `cairn.sidecar` subprocess over stdio JSON-RPC

See `README.md` for the user-facing description, `docs/architecture.md`
for internals, `docs/configuration.md` for profile tuning.

## Invariants — do not break

### Honesty about calibration

The system is in heuristic mode by default — no trained EBM fusion, no
calibrated conformal wrapper, hand-picked per-detector p(LLM) tables. The
UI announces this with a banner; `/health` reports
`calibration_status: "heuristic"`.

- **Detector-internal constants that map raw signal → p(LLM) must be
  named `_HEURISTIC_*`** (see `fingerprint_vocab.py`, `instruction_density.py`,
  `preamble.py`, `perturbation.py`, `contrastive_gen.py`). Do not relabel
  them as "calibration" tables — that reads as empirical ground truth
  when they are not.
- **`prediction_set` is cosmetic severity bands** (RED/AMBER/...).
  **`conformal_set` is the honest binary set** (`["LLM"]` / `["human"]` /
  `["human", "LLM"]`) — populated only when a calibrated conformal wrapper
  is loaded. Never conflate them.
- **`fusion_mode: "naive"` → "contributions" are deviations-from-prior**,
  not additive feature attributions. The UI caveats this; preserve the
  distinction in any new surface.

### Detector failures surface, not swallow

`pipeline._run_phase` logs and records detector failures to
`Determination.detector_errors` (+ UI banner). Do not add bare
`except Exception: pass` around detector calls. If a new detector can
fail partially, include enough in the `signals` dict or `error` field
to diagnose.

### Privacy boundaries

- `contrastive_gen` sends **only the task description** to the provider,
  never the submission text. There's a test asserting this — keep it
  passing.
- **`task_description.auto_mode`:** `local` derives on-host (safe default
  when auto is enabled). `llm` **sends the submission** to the provider
  for summarization — opt-in only; pipeline surfaces a leak warning on
  the determination. Default config keeps `auto_mode: off`.
- `gui.history.retain_text` defaults to **false** (hash-only). Don't
  flip the default without flagging it as a privacy change.
- `_redact` in `cairn/api.py` walks the full config and scrubs keys
  matching: `secret, api_key, apikey, token, password, passwd,
  credential, auth`. Extend if you find new sensitive key patterns.

### Cascade-phase membership

`cairn/cascade.py::PHASE{1,2,3,4}_DETECTORS` is the source of truth for
what runs when. If you change it, update `README.md`'s Phase table
accordingly (they drifted apart once and got a review callout).

## Code conventions

- **Python 3.11+ with type hints on public surfaces.** Dataclasses for
  contracts (`cairn/contracts.py`); `Protocol` for structural typing.
- **Stdlib at boundaries.** `http.server`, `sqlite3`, `json`. External
  deps are fine for algorithms (`interpret`, `scikit-learn`,
  `transformers`, `sentence-transformers`) behind extras.
- **Optional deps load lazily.** `torch`, `transformers`, `anthropic`,
  `openai`, `sentence-transformers` — import inside the function that
  needs them. The base install must stay tiny.
- **Dataclasses add fields with defaults**, never reorder existing
  ones. `Determination` and `FusionResult` are consumed by tests,
  reports, and the UI.
- **Best-effort writes** for history, drift, audit. A failed side-channel
  write must never fail the analyze RPC. Log to stderr and continue.

## Tests

`pytest` with ~80 test modules covering contracts, detectors, router,
cascade, fusion, decision, calibration, evaluation, monitoring,
privacy, provenance, history, HTTP API, sidecar RPC, availability
introspection, evaluation serialization.

Structural tests (did the field land, did the RPC round-trip, does
this detector fire on this fixture) — **they do not establish
empirical accuracy**. Don't write tests that tautologically assert
the heuristic constants (e.g. `p_llm >= 0.75` because the preamble
table says so). Write tests that assert *behavior* — spans land,
errors surface, conformal set is binary when calibrated.

Run the full suite: `pytest -q`. Expect ~760+ passing (count drifts with new tests).

## Adding a detector

1. Create `cairn/detectors/your_detector.py` implementing the
   `Detector` protocol from `cairn/contracts.py`.
2. Register in cascade (`cairn/cascade.py::PHASE{1,2,3,4}_DETECTORS`).
3. Add default entry in `configs/default.yaml::detectors`.
4. Add a test in `tests/test_detectors/test_your_detector.py`.
5. If the detector has positional evidence (regex matches, token
   offsets), populate `spans` on the `LayerResult` and add a
   `.span-<kind>` CSS class in `cairn/gui/static/index.html` if your
   `kind` isn't already in the palette.
6. If the detector needs extras, list them in `pyproject.toml` under
   the relevant extras group (`tier2`, `tier3`, etc.) and have the
   module degrade with a clear SKIP signal when the import fails.
7. Update `cairn/pipeline.py::detector_availability` if the detector
   has a runtime requirement that can't be detected by registry-load
   alone (API key, batch context, etc.).

## Adding an RPC method — 4 touch points

Both transports route to shared code. A new method needs:

1. Method body on `Sidecar` class in `cairn/sidecar.py` (or a helper).
2. Dispatch entry in `Sidecar.handle`.
3. HTTP route in `cairn/gui/server.py::_make_handler`.
4. Tauri command in `src-tauri/src/commands.rs` + registration in
   `src-tauri/src/main.rs::invoke_handler`.

Plus tests in `tests/test_rpc_sidecar.py` and `tests/test_http_api.py`.
Plus `cairnApi` entry in both branches of `cairn/gui/static/index.html`.

## Working with the UI

`cairn/gui/static/index.html` is one big file by design. When adding UI:

- API client entries go in **both** branches of `cairnApi` (Tauri
  `invoke` and HTTP `fetch`) — keep the signatures identical.
- Tabs register in the `VIEWS` array + the `showTab` switch and get a
  `loadX` loader invoked when the tab becomes active.
- Span highlight colors use the `.span-<kind>` CSS pattern; new kinds
  add a class + a chip in the legend's `KIND_LABELS` map.
- Don't break the `window.__TAURI_INTERNALS__` detection — the single
  file has to work in both fetch-mode (web) and invoke-mode (Tauri).

## Things the project does NOT have yet (don't pretend it does)

- **Auth / rate limiting on by default.** Bearer auth and sliding-window
  rate limits exist (`cairn/security/`) but are **opt-in** via config
  (`auth.tokens`, `rate_limit.enabled`). Loopback bind is still the
  default deployment story; don't assume the gate is active without checking
  `/health` (`auth`, rate-limit fields).
- A non-loopback hardening story for `cairn serve`. Front with a
  reverse proxy if exposed beyond a single machine.
- **Profile auto-routing on by default.** `RuntimeContext.switch_profile()`
  is manual unless `runtime.auto_route: true` in config — then
  `cairn/auto_routing.py` picks among calibrated profiles. Default YAML
  keeps `auto_route: false`; treat routing as deployment-time unless
  explicitly enabled.
- A persistent DriftMonitor window. Baselines rebuild from the
  history store on demand, but the in-flight observation window
  is lost on sidecar restart.

## Things the project DOES have now (recent additions)

- **Calibrated profiles** under `models/calib2000/profiles/` —
  trained EBM + isotonic + split-conformal artifacts for 13+
  profiles. Production recommendation: `master_minus_arxiv` for
  prose, `prompts_only` for prompts. See
  `docs/benchmarks/README.md` for the full grid.
- **Feature cache** (`cairn/feature_cache.py::CachedPipeline`) —
  sha256-keyed detector output cache that makes profile-grid /
  LOO experiments tractable (~3 min retrain vs ~1–2 hr).
  `data/all_features_v6.jsonl` is the master cache; see
  `docs/calibration.md`.
- **Multi-provider calibration corpus** — ~94K rows
  (`data/calib2000_v6_train.jsonl`) across six providers and
  multiple genres. Built by `scripts/regenerate_llm_outputs.py`
  + `scripts/regen_domain_calib.py`.
- **Held-out OOD validation** — M4 / RAID / MAGE samples at
  `data/ood_*_test.jsonl`. Use them to validate any profile
  change.
- **Prompt detection corpus** — ~30K provenance-clean human +
  LLM-generated prompts at `data/prompts_*.jsonl`, supporting
  the `prompts_only` profile.
- **Length-aware EBM features** — `log_word_count`, `is_short`
  / `is_medium` / `is_long`. EBM `interactions=15` (was 5).
- **Modal GPU offload** for feature caching —
  `scripts/modal_cache_features.py`.
- **Full-coverage research profile** —
  `configs/.profile_full_coverage.yaml`. Bypasses cascade short-circuit
  so every detector fires on every sample. The recommended input
  profile when caching features for a new calibrator pass — production
  benchmarks under the default cascade understate phase-2/3 detector
  strength because each detector only sees its "ambiguous-middle"
  slice. See `docs/configuration.md` (cascade section) for tradeoffs;
  not a production deployment target.

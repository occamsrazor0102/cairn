# CAIRN — LLM Authorship Detection

A multi-detector fusion pipeline for classifying whether a piece of text
was written by a human or generated by a large language model. CAIRN
combines pattern-based, statistical, and LLM-backed detectors into a
single calibrated verdict with a confidence interval and per-feature
contributions.

The project ships three runtimes that share one pipeline:

- **`cairn gui`** — local web UI with tabs for analyze, batch, history,
  monitoring, evaluation, and settings.
- **`cairn serve`** — FastAPI REST service for integrations.
- **Tauri desktop shell** — packaged `.msi` / `.dmg` / `.AppImage`
  wrapping the same UI over a stdio sidecar.

## Quick start

```bash
pip install -e .

# web UI on http://127.0.0.1:8877 — heuristic mode (no calibration)
cairn gui --profile screening

# or with the production calibrated profile
cairn gui --profile calibrated_calib2000
```

Paste text, click Analyze. The result panel shows:

- **Determination** — RED / AMBER / YELLOW / GREEN / UNCERTAIN / MIXED
- **P(LLM)** with a conformal confidence interval
- **Top contributing signals** from the EBM fusion model
- **Detector breakdown** — per-layer raw score, calibrated p(LLM),
  confidence, verdict, and signals
- **Highlighted text** — character-span overlays showing which phrases
  triggered which detector

## What's in the box

### Detectors

Twenty-one detectors organised into four cascade phases:

| Phase | Cost | Detectors |
|------:|------|-----------|
| 1 | trivial / cheap | `preamble`, `fingerprint_vocab`, `prompt_structure`, `voice_spec`, `instruction_density`, `nssi`, `compression_profile`, `typographic_signature` |
| 2 | moderate | `surprisal_dynamics`, `contrastive_lm`, `fast_detectgpt`, `token_cohesiveness`, `mixed_boundary`, `semantic_kinematics`, `specdetect`, `reasoning_artifact` |
| 3 | expensive (LLM-backed) | `perturbation` (disabled; superseded by `fast_detectgpt`), `contrastive_gen`, `dna_gpt`, `lapd` |
| 4 | batch-only | `cross_similarity` (and `contributor_graph` via `pipeline.analyze_contributors`) |

The cascade scheduler short-circuits on confident Phase 1 verdicts and
only invokes expensive Phase 3 detectors when the cheaper signals are
inconclusive.

Nine of the detectors emit **character-level spans** pointing at the
specific tokens that triggered them (preamble, fingerprint_vocab,
instruction_density, nssi, voice_spec, prompt_structure,
compression_profile, typographic_signature, reasoning_artifact) —
surfaced as highlights in the UI. `reasoning_artifact` is the first
Phase-2 detector to do so; the rest are Phase 1.

`compression_profile`, `typographic_signature` and `reasoning_artifact`
are the 2026-08-26 slate and ship **disabled**: they are wired into the
cascade and the EBM assembler but contribute nothing until a feature
cache is rebuilt and the profiles retrained. See
[`docs/retrain-with-new-detectors.md`](docs/retrain-with-new-detectors.md).

### Fusion, calibration, decision

- **EBM fusion** (interpret-ml Explainable Boosting Machine) combines
  per-detector `p_llm` scores with calibrated contributions.
- **Isotonic calibration** per detector from a labeled dataset.
- **Conformal prediction** for a valid P(LLM) confidence interval.
- **Decision engine** maps fused P(LLM) to RED / AMBER / YELLOW / GREEN
  with configurable thresholds, abstains to UNCERTAIN when the
  prediction set is too wide, and enforces override rules (e.g. a
  CRITICAL `preamble` match short-circuits to RED).

### Calibrated profiles (production)

Trained EBM + isotonic + split-conformal artifacts ship for several
profiles built from the **calib2000 v6 corpus** — ~94K human/LLM rows
spanning six providers (Anthropic / OpenAI / Gemini / Mistral /
DeepSeek / Moonshot), HC3's five subdomains, OOD samples from M4 /
RAID / MAGE, domain prose (arXiv, GSM8K, HumanEval), and ~30K
provenance-clean prompts.

| Profile | Best for | Notes |
|---------|----------|-------|
| `calibrated_calib2000` | Default production | Six-provider full corpus; most provider-diverse |
| `general_hc3` | In-domain prose, controls | Pure HC3 — peak in-distribution AUROC (0.94) |
| `master_minus_arxiv` | Cross-domain prose, RAID/MAGE, short-form | Beats `everything` on 6/9 tests after dropping arxiv drag |
| `prompts_only` | Prompt detection | Trained only on the 30K prompt corpus |
| `medical` / `finance` / `stem` | Domain specialists | Source-tag-filtered subsets |

See [`docs/calibration.md`](docs/calibration.md) for how the corpus
was built and how to train your own profile, and
[`docs/benchmarks/README.md`](docs/benchmarks/README.md) for full
profile-grid + OOD numbers.

### Built-in observability

- **SQLite history store** — every analyze/batch call is logged and
  queryable by the History tab.
- **Monitoring dashboard** — determination distribution, per-day
  volume, 200-point recent-submissions scatter, per-detector
  aggregate stats, feedback-derived accuracy and Brier score.
- **Drift monitor** — KL divergence per feature against a baseline you
  seed from recent history; population and calibration drift alerts.
- **Evaluation runner** — wraps `cairn.evaluation.runner.run_eval`
  inside the UI with AUROC / ECE / Brier / TPR@FPR / per-tier and
  per-attack breakdowns plus a confusion matrix.
- **Hash-chained audit log** for provenance (`cairn.provenance.chain`).

## Running the tests

```bash
pip install -e ".[dev]"
pytest
```

~80 test modules (~760+ passing) covering contracts, detectors, router,
cascade, fusion, decision, calibration, evaluation, monitoring,
privacy, provenance, history, the HTTP API, and the sidecar RPC.
These are structural tests (did the field land in the report, did
the RPC round-trip, does this detector fire on this fixture); for
empirical accuracy see the calib2000 benchmarks.

## Development loop

For the desktop shell, see `docs/building.md`. For web-UI changes,
`cairn gui` reloads `index.html` on every request (it's a static file),
so frontend iteration is a browser refresh.

For backend changes, restart `cairn gui`. The stdio sidecar is
restarted by the Tauri shell on relaunch.

## Limitations — read before deploying

CAIRN now ships trained EBM + isotonic + split-conformal artifacts
for several profiles, but several caveats still apply:

- **Four fusion tiers coexist.** `/health` reports
  `calibration_status` as one of:
  - `heuristic` — no trained EBM, no conformal. Fusion falls back to
    naive weighted-mean across detector `p_llm` values; the GUI shows
    an "untrained" banner. The `default` / `screening` / `strict` /
    `no-api` / `production` profiles run in this tier.
  - `fusion-only` — trained EBM is loaded but the conformal artifact
    is missing or uncalibrated. `p_llm` is calibrated, `conformal_set`
    is empty.
  - `calibrated` — EBM + split-conformal both loaded. `conformal_set`
    is populated with marginal coverage at the calibrated alpha.
  - `calibrated-router-conditional` — additionally, the conformal
    artifact carries per-router-class thresholds (Phase 3 v3 schema),
    so coverage is class- *and* router-stratified. The
    `master_minus_arxiv`, `prompts_only`, and other production
    profiles under `models/calib2000/profiles/` ship at this tier.
- **Heuristic mode uses hand-picked detector tables.** When no
  `detector_calibration_path` is loaded, the `_HEURISTIC_*` constants
  in `preamble`, `fingerprint_vocab`, `instruction_density`,
  `contrastive_lm` etc. drive each detector's `p_llm`. Calibrated
  profiles override these via `DetectorCalibrator`
  (`cairn/calibration.py`).
- **Conformal coverage assumes in-distribution test data.** The
  split-conformal wrapper provides marginal coverage at the calibrated
  alpha (default 0.05) when the test distribution matches the
  calibration set. OOD data (MAGE / RAID / unseen providers) breaks
  this assumption — the prediction set widens but coverage is no
  longer guaranteed.
- **Tier-3 detectors are implemented but opt-in.** `perturbation`
  runs a real DetectGPT-style log-prob curvature score (requires
  `cairn[tier2]` for `torch`+`transformers`; loads `distilgpt2` by
  default, roughly 300MB). `contrastive_gen` generates k baselines
  via an LLM provider and compares via shingle Jaccard or
  sentence-transformers embeddings (requires `cairn[tier3]` +
  `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`). `dna_gpt` truncates the
  text at 30/50/70% and scores n-gram overlap of provider
  continuations (same tier-3 requirements).
- **`contributor_graph` and `cross_similarity` are batch-only.** They
  return `SKIP` on single-text analyze; `cross_similarity` runs on
  `pipeline.analyze_batch`, `contributor_graph` via a separate
  `pipeline.analyze_contributors` entry point.
- **Weak detectors are being replaced, not just disabled.** Per-detector
  AUROC analysis surfaced detectors with near-zero discriminative power on
  calib2000 (`token_cohesiveness` 0.50, `mixed_boundary` 0.51, `preamble`
  0.52, `fingerprint_vocab` 0.54) plus `surprisal_dynamics`, which inverts
  OOD. The in-flight remediation:
  - `token_cohesiveness` was a divergent TOCSIN approximation (MiniLM
    cosine, single-token deletion); it is now a faithful TOCSIN rebuild
    (BART-base cohesiveness + a Fast-DetectGPT base channel, EMNLP 2024).
  - `fast_detectgpt` (analytic conditional-probability curvature,
    arXiv:2310.05130) is added in Phase 2 and supersedes the classic
    `perturbation` detector (now disabled).
  - `surprisal_dynamics` keeps its (OOD-inverting) heuristic *suppressed*
    and now exports DivEye-style fluctuation features (arXiv:2509.18880)
    for the EBM to map.
  - `preamble` / `fingerprint_vocab` / `mixed_boundary` stay enabled
    (high-precision in heuristic mode / drive the mixed report); dropping
    them from a calibrated profile's fusion is a retrain-time LOO call.
  All require a fresh EBM/conformal retrain to take effect (the assembler
  emits the new columns; existing artifacts ignore them until retrained).
- **The Settings tab shows what's really active.** Each declared
  detector is tagged "available" or flagged with its missing
  requirement (tier2 / tier3 / API key / batch-only).
- **Detector failures are surfaced, not swallowed.** If a detector
  raises during analyze, the failure is logged and reported back on
  `Determination.detector_errors`; the UI shows a red "reduced
  coverage" banner in the result panel.
- **OOD performance varies by distribution.** The production
  `master_minus_arxiv` profile delivers AUROC ~0.94 in-domain (HC3
  prose), ~0.68 on RAID, ~0.57 on MAGE, and ~0.89 on `verbosity=low`
  short-form. Performance on a deployment's actual input
  distribution may differ; recalibrate against a matched-genre
  sample if possible. See [`docs/benchmarks/README.md`](docs/benchmarks/README.md).
- **OpenAI hidden-reasoning is the stealthiest target.** Per-provider
  matched-comparison eval shows OpenAI Responses API reasoning text
  ~6 AUROC points harder to detect than other frontier providers.
- **Regression tests encode contracts, not accuracy.**
  `test_regression.py` asserts structural properties (the field
  lands, the spans render); empirical accuracy is verified against
  the calib2000 benchmark suite.
- **Tier-3 detectors require API credentials.** `pip install -e ".[tier3]"` plus provider env vars.
- **`run_eval` inside the GUI is capped at 1000 samples.** Drop to
  `cairn.evaluation.runner.run_eval` in Python for larger runs.
- **DriftMonitor observations are in-memory.** Baselines are rebuilt
  from the persistent history store on demand, but the current
  window is lost on sidecar restart.
- **No auth or rate limiting on the HTTP/FastAPI transports.** The
  GUI binds to `127.0.0.1` by default; `cairn serve` on a
  non-loopback interface ships without authentication. Front with a
  reverse proxy (oauth2-proxy, nginx basic-auth) if you expose it
  beyond a single machine.
- **Heuristic detectors are genre-sensitive.** `fingerprint_vocab`,
  `nssi`, and `prompt_structure` were seeded with words and patterns
  common in LLM output — but many of those patterns are *also*
  common in disciplined human writing (SOPs, clinical protocols,
  legal briefs, educational material). The trained EBM accounts for
  this on calibrated profiles; in heuristic mode, expect false
  positives on polished domain prose.

If you're deploying somewhere users will see the verdicts: pick a
calibrated profile (`master_minus_arxiv` recommended for prose,
`prompts_only` for prompt detection), benchmark it against a sample
of your actual input distribution, and tune
`decision.*_threshold` to the precision/recall trade-off your use
case requires.
